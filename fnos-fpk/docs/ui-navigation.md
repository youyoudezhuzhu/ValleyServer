# 导航与路由（0.2.13 起）

## 1. 一级导航：10 项 → 5 项

| # | 一级入口 | 路由 | 二级标签 |
| :-- | :--- | :--- | :--- |
| 1 | 总览 | `#dashboard` | （无） |
| 2 | 游戏管理 | `#game/<section>` | 运行与日志 · 存档 · 模组 · 崩溃诊断 |
| 3 | 备份与恢复 | `#backup/<section>` | 快照 |
| 4 | 设置与维护 | `#settings/<section>` | 运行设置 · 显示与访问 · 备份设置 · 游戏与运行环境 · 版本管理 · 高级 · 维护记录 |
| 5 | 任务与诊断 | `#tasks/<section>` | 任务队列 · 健康与诊断 |
| — | 关于（侧栏底部） | `#about` | （无） |

## 2. 旧路由兼容映射

旧书签、旧页内跳转**全部继续可用**：`parseRoute()` 会把旧 hash 映射到新路由，
并用 `history.replaceState` 把地址规范化（不产生历史记录跳转）。

| 旧路由 | 新路由 | 说明 |
| :--- | :--- | :--- |
| `#dashboard` | `#dashboard` | 原样保留 |
| `#console` | `#game/runtime` | 原「控制台」的日志区（任意指令面板已于 0.2.27 移除，见 known-issues I-54） |
| `#saves` | `#game/saves` | |
| `#mods` | `#game/mods` | 显示名统一为「模组」 |
| `#snapshots` | `#backup/snapshots` | |
| `#versions` | `#settings/version` | 归入「设置与维护 › 版本管理」 |
| `#config` | `#settings/runtime` | 整页仍可用（`PAGES.config` 渲染全部四组设置） |
| `#system` | `#settings/environment` | 整页仍可用（`PAGES.system` 渲染全部区块） |
| `#tasks` | `#tasks/queue` | |
| `#about` | `#about` | |

**未知路由的回落**：未知一级 → 总览；未知二级 → 该入口的默认二级。
**一级入口不带二级**（如 `#game`）→ 自动落到默认二级。
**不会死循环**：路由解析是纯函数，`refresh()` 只做一次规范化。

## 3. 页面职责划分

| 旧页面 | 去向 | 说明 |
| :--- | :--- | :--- |
| 控制台（日志 + 诊断；任意指令面板已移除） | 游戏管理 › 运行与日志 / 崩溃诊断 | 日志在默认视图，**指令区标为「高级」**；崩溃诊断独立成二级页 |
| 存档 | 游戏管理 › 存档 | 导入 / 导出 / 切换 / **恢复存档** / 删除 |
| MOD | 游戏管理 › 模组 | 已安装 · 安装模组（单个） · 安装服务器组件 · 诊断结果 |
| 快照 | 备份与恢复 › 快照 | 创建 / 校验 / 详情 / 下载 / **恢复整个快照** / 删除 / 保留策略 |
| 版本 | 设置与维护 › 版本管理 | 回滚**链接**到快照，不复制一套实现 |
| 配置 | 设置与维护 › 运行设置 / 显示与访问 / 备份设置 / 高级 | 四组分开；**跨标签共享同一份草稿**，任一标签都能「保存并应用」 |
| 系统 | 设置与维护 › 游戏与运行环境 / 高级 / 维护记录 + 任务与诊断 › 健康与诊断 | 安装/下载/升级类耗时操作集中在「游戏与运行环境」，与普通设置表单分开 |
| 任务 | 任务与诊断 › 任务队列 | |

**没有任何 API 或功能被删除**：所有原有接口与操作都还能在新 UI 里找到
（`GET /api/*` 与 `POST /api/*` 全集保持不变）。

## 4. 统一状态模型

需求要求区分两个**正交**维度，界面必须同时表达、不能互相替代：

| 维度 | 取值 | 数据来源 |
| :--- | :--- | :--- |
| **服务运行状态** | 未启动 / 启动中 / 运行中 / 停止中 / 已停止 / 启动失败 / 状态未知 | `readiness.service.state` |
| **农场开服状态** | 尚未创建存档 / 尚未载入农场 / 农场已载入 / 开服状态待确认 | `readiness.farm.state` |

* 两者都带 `hint`（可操作建议）；
* 健康检查仍分四层：游戏进程 / 显示环境 / 端口监听 / SMAPI 加载；
* 视觉上**图标 + 文字 + 颜色**三者同时表达（`.state-badge`），不单靠颜色；
* 侧栏底部同时显示两个维度的迷你状态；
* 「农场已载入」的判据是**游戏端口（UDP）已监听**，绝不是"进程在跑"。

## 5. 术语规范（用户可见文案）

| 概念 | 统一用词 |
| :--- | :--- |
| 一级菜单 / 数据管理对象 | **模组**（正文首次出现可写「模组（MOD）」） |
| 数据管理 | **存档**；只有描述游戏世界时才说「农场」 |
| 带校验清单的备份 | **快照** |
| 单个存档恢复 | **恢复存档** |
| 整套数据恢复 | **恢复整个快照** |
| 版本操作 | **更新游戏本体** / **更新 SMAPI** / **回滚游戏版本** |
| 上游官方组件（ALOS、ServerCMD…） | **服务器组件** |
| 运行实体 | **游戏进程** / **显示环境** / **运行环境**（不再使用容器化词汇） |
| 设置项标签 | ≤6 汉字；说明 ≤20 字（安全说明可略长） |

## 6. 响应式（三档）

| 断点 | 布局 |
| :--- | :--- |
| > 1100px（桌面） | 完整侧栏（图标 + 文字）、多列卡片、正常表格 |
| 720–1100px（平板） | 侧栏仅图标；卡片列数减少；两列布局折成单列 |
| < 720px（手机） | 侧栏变顶部横向导航；卡片单列；**表格转卡片**（用单元格的 `data-label` 当字段名）；长路径与校验值允许换行，避免横向滚动；弹窗留边距、按钮自动换行 |

表格的卡片化依赖 `table()` 助手为每个 `<td>` 写入 `data-label`，
以及 `table.responsive` 类（两处都在自动化测试里断言）。

## 7. 不可破坏的约束（重构后仍然成立）

1. 「Steam 扫码登录」「下载获取游戏」「启动服务端」三步互相独立，不自动串联；
2. 没有存档时**不自动创建**，提示「需手动新建存档并重启服务端」；
3. 服务启动成功 ≠ 农场已开服（两个维度分开表达）；
4. WebVNC 与 CommandWebUI 无认证的风险提示保留（默认「监听范围 = 所有网络接口」，
   选「仅本机」时真正只对 VNC/WebVNC 绑定回环；CommandWebUI 不受约束，文案已如实说明）；
5. 所有请求仍用**相对路径**（网关 iframe 兼容），不引用外网资源；
6. 会话 Cookie / CSRF / 网关认证逻辑不变；
7. 危险操作分级确认（普通 / 有影响 / 高风险 / 破坏性需输入对象名）+ 变更前自动快照；
8. 不引入前端框架与构建步骤（仍是手写原生 JS）。
